# Перевод премиум-модулей NWN:EE и доставка через Steam Workshop

Итог исследования 2026-06-23 (модуль «Тёмные грёзы Фурии» как полигон). Здесь —
как переводить платные DLC-модули и как раздавать перевод через Workshop.

## TL;DR

- Текст премиум-модуля лежит **внутри** `.nwm/.mod` как embedded LocStrings
  (английский инлайн, `strref = -1`), а НЕ в общем `dialog.tlk`. Поэтому
  tlk-подход неприменим — правим ресурсы внутри модуля.
- **Доставка — через хак самого модуля** (2026-07-12). Кладём переведённые ресурсы
  в тот хак, который модуль уже перечислил в `Mod_HakList`, и раздаём этот хак
  подпапкой `hak/` айтема. Хак (`31M`) перебивает модуль (`20M`) и грузится
  ТОЛЬКО своим модулем → кампания и чужие модули не затронуты. Журнал переводится.
- **`development/` (71M) — глобальный слой, применяется ко ВСЕМ модулям.** Отсюда
  главный баг первой версии: `module.jrl` оттуда подменял журнал оригинальной
  кампании → `ERROR, blank journal entry`. В `development/` нельзя класть ничего,
  чьё имя совпадает с ресурсом другого модуля (`module.jrl`, `area001.are`, …).
- **НЕ работает:** `override/` (`12000000`, ниже модуля), `data/nwm/*.nwm`
  (Workshop вообще не монтирует `data/`).
- **Экран выбора кампаний** (`repository.json`) Workshop доставить **не может**
  ни одним слоем — лечится только локальным `patch_repo.py`.
- **Раздача легитимна** через Workshop с флагом required-DLC: Steam отдаёт айтем
  только владельцам нужного DLC.

## 1. Где лежит текст

Премиум-модуль — это ERF (`MOD V1.0`). Локализуемые поля — `CExoLocString`
внутри GFF-ресурсов (DLG/UTC/UTI/ARE/GIT/JRL/…). У Furiae и DoID `Mod_CustomTlk`
пуст → строки встроены инлайн (`strref = -1`). База игры наоборот: её текст в
общем `dialog.tlk` (потому базовый перевод и доставляется простым override).

## 2. Пайплайн перевода (общий для embedded-LocString модулей)

1. `context/ddf_prep.py --nwm <MOD>.nwm --out <dir>` — извлекает уникальные
   английские строки (дедуп), группирует по ресурсу (контекст диалога рядом),
   пишет батчи `<dir>/batches/NNNN.json` + `<dir>/index.json` (id → все вхождения
   `(resref, restype, path)`). Обобщён на любой такой модуль.
2. `context/wf_module.js` — Workflow: перевод батчей (глоссарий + код-валидация
   тегов `<CUSTOM…>` + repair), пишет `<dir>/translated/NNNN.json` = `{id: ru}`.
3. `context/ddf_apply.py` — вписывает русский (CP1251) во все вхождения LocString,
   перепаковывает ERF → `<MOD>_ru.nwm`. Писатели `context/gff.py` + `context/erf.py`
   доказаны байт-в-байт (неизменённый модуль пересобирается идентично).

NSS-скрипты (хардкод-барки/всплывашки) — отдельная сложная тема, не трогаем
(меньшинство текста).

## 3. Слои ResMan: кто кого перебивает

Приоритеты (источник: nwn.wiki «Content Load Order», числа заданы в коде движка
как `RESMAN_PRIORITY_*`, шаг 1 000 000; подтверждено логом `logs/nwengineLog.txt`):

```
development/ (71M)  >  NWSync (40M)  >  hak (31M user / 30M install)  >
   модуль .mod/.nwm (20M)  >  override/ (12M)  >  ovr (10M)  >  база .bif (1M)
```

Workshop монтирует подпапки айтема в **одноимённые алиасы по имени, без бело-листа**
(бинарь `nwmain`: `SteamWorkshopDiscoveryRepository::SetupData` → generic
`GetDirectoryList`). Поэтому подпапка `hak/` айтема встаёт на User Hakpack (31M),
а `development/` — на 71M.

Ключевая разница между слоями — **область действия**:

| слой | перебивает модуль? | к каким модулям применяется |
|---|---|---|
| `development/` (71M) | да | **ко всем** — глобальный, модуль не различает |
| hak (31M) | да | **только к тому**, кто перечислил хак в `Mod_HakList` |
| `override/` (12M) | нет | ко всем, но модуль его перекрывает |

## 4. Доставка перевода: через хак модуля (2026-07-12)

**Хак — единственный слой, который и перебивает модуль, и привязан к нему.**
Правка модуля при этом НЕ нужна (в прошлой редакции этого файла было написано
обратное — ошибка): подменяем не «свой новый» хак, а тот, который модуль **уже**
подключает. Все восемь премиум-DLC его подключают:

```
DDF        ddf                    Daggerford  dodee_hf0_lib, dodee_dev, dodee_tno_addons
DoID       doiwd                  Moonsea     tm_hf0_lib + 9 других
ID         id_resources           Cormyr      wc_top + 6 других
Kingmaker  km_resources           Pirates     potsc_top, potsc_resources
ShadowGuard sg_resources          Witch's Wake ww_resources
```

Приоритет между хаками — **по порядку в `Mod_HakList`, первый главнее** («the
highest (first loaded) hakpack takes precedence»). Поэтому берём ПЕРВЫЙ хак списка:
у Daggerford и Moonsea это крошечные `dodee_hf0_lib` (984 КБ) и `tm_hf0_lib` (1.1 МБ),
а не 195/114-мегабайтные ассет-паки.

Важно: userdir-хак **подменяет** установочный целиком, а не дополняет его. Поэтому
в айтем кладётся полная копия хака (оригинал + наши ресурсы). Проверено на живой
игре: маленький `ddf.hak` с одним `module.jrl` убил ассеты модуля (двери без
моделей, скайбокс, зависание при переходе в город); полный `ddf.hak` (676 МБ
оригинала + 15 МБ перевода) дал полностью русский DDF, включая журнал, при целой
кампании.

Сборка: `context/build_workshop_haks.py` → `hak/<первый хак>.hak` + шрифты.
Базовый айтем: `context/build_workshop_base.py`. Оформление: `context/finalize_workshop.py`.

## 4b. Мина `development/`: одинаковые имена ресурсов

Первая версия айтемов раскладывала переведённые ресурсы loose в `development/`.
Это работает (перевод виден), но слой **глобальный**, а имена ресурсов в NWN — это
плоский `ResRef` + тип, без неймспейсов. Итог: `development/module.jrl` подменял
журнал **любого** запущенного модуля. Игрок с базовым переводом заходил в пролог,
скрипт просил категорию `JOUR_M1Q0Training`, а в загруженном журнале лежали две
категории из бонус-модуля → движок писал `ERROR, blank journal entry: JOUR_M1Q0Training`
(строка захардкожена в `nwmain`, не в TLK). Так же подменялись `area001.are`
(«Форт Илкард» в главе 3), `creature001.utc`, `nw_cloth029.uti` и ещё десятки имён.

Правила для `development/`, если он всё-таки нужен (бонус-модули без хаков):

- **никогда** не класть `module.jrl` и `module.ifo` (имя одно на все модули);
- вычищать всё, чей `(resref, restype)` встречается в базовой игре — чёрный список
  строится из `data/nwm/*.nwm` (см. `build_workshop_base.py`);
- расширение файла определяет тип ресурса для движка: `UTP`, записанный как `.utd`,
  просто не будет виден (в первой версии так молча терялся перевод дверей,
  плейсаблов, магазинов, встреч, звуков и вейпоинтов — 57 файлов на DDF).

## 4c. Что НЕ работает (проверено в игре)

- `override/` — ниже модуля (12M < 20M), внутренности `.nwm` не достаёт.
- `data/nwm/*.nwm` в айтеме — `data/` не монтируется Workshop вообще.
- `SetTlkOverride` — только по strref; у нас embedded (`strref = -1`), N/A.
- подпапки внутри `development/` (`development/treasure/module.jrl`) — движок их
  не читает вовсе; имя папки неймспейса не создаёт.
- переименование ресурса (`treasure.jrl`, `The Dark Ranger's Treasure.jrl`) — движок
  запрашивает журнал строго по имени `module`, такой файл никто не спрашивает.
- loose-файл в папке `hak/` — там читаются только `.hak`-архивы из `Mod_HakList`.
- `.mod` в `modules/` под именем установочного — не перекрывает `data/mod`, а
  дублирует модуль в группе «Локальные».
- NWSync (40M) — монтируется только при коннекте к серверу, для одиночной игры N/A.

## 4d. Бонус-модули: у них нет хака, и это тупик

Пять бесплатных модулей идут с игрой (`data/mod/`): Neverwinter Chess,
Contest of Champions, The Dark Ranger's Treasure, The Winds of Eremor, To Heir is Human.
У всех пяти **`Mod_HakList` пуст** — цеплять перевод не к чему, хак они не загрузят.
Всё, кроме журнала, доставляется им через `development/` (с чёрным списком, см. 4b).

Журнал же требует слоя выше модуля, а такой без хака только один — глобальный
`development/`. Значит либо журнал остаётся английским (3 модуля, 5 категорий),
либо мы кладём туда журнал, который знает теги ВСЕХ модулей.

**Мега-журнал** (`context/build_mega_jrl.py`) — объединённый `module.jrl` всего
официального контента: кампания + SoU + HotU + 8 DLC + бонусы = 597 категорий,
3000 записей, 1.14 МБ. Отдельный **opt-in** айтем «AI Russian Text Journals»
(видимость: скрытый), потому что цена высокая: любой пользовательский модуль, чьих
тегов там нет, получает `ERROR, blank journal entry` — включая кураторские модули,
которые игра показывает сама (Aielund Saga и прочие).

Теги квестов уникальны только внутри своего модуля, поэтому при слиянии есть
коллизии: 16 записей с одинаковым `(тег, ID)` и разным текстом. Например `MainPlot`
есть и у Cormyr, и у «Ветров Эремора»; `Henchman` — у кампании (в каждой главе свой
текст!) и у «Сокровища». Такие записи склеиваются: показываются оба варианта, каждый
с подписью `[ модуль ]`.

Единственный способ дать бонус-модулям журнал без глобального оверрайда — патчить
их `.mod` на диске (8.9 МБ на пятерых), то есть локальный установщик, не Workshop.

## 5. Экран выбора кампаний (`repository.json`) — отдельная стена

Названия/описания кампаний в лаунчере («Классические кампании / Вопящая смерть»)
берутся из `<install>/data/{mod,nwm}/repository.json` (gamedata, литеральные строки,
не strref). Лаунчер строит 4 ГРУППЫ репозиториев (Официальные=gamedata /
Сообщество=workshop / Премиум / Локальные); Workshop-контент попадает в «Сообщество»,
а не поверх «Официальных». **Исчерпывающе проверено** (10 раскладок: workshop `data/`,
корень, `modules/`, `development/`, userdir-`data/`, реальный `SteamWorkshopDiscovery`
в корень+`modules/`) — ни одна не кормит Официальную группу. Вывод: Workshop этот
экран перевести НЕ может; это install-gamedata.

Локальный фикс: **`patch_repo.py`** — кросс-платформенный, патчит установочные
`data/{mod,nwm}/repository.json` (overlay RU по uuid + CP1251-remap, бэкап
`.en.bak`, идемпотентен). Чтобы переживало апдейты Steam — в Steam Launch Options:

```
python3 /полный/путь/patch_repo.py && %command%
```

(патчер прогоняется перед каждым запуском). Подписчикам экран остаётся английским —
косметика; UI и весь текст В игре русские. В описании айтема — одна строка-приписка.

## 6. Раздача и права

Раздавать перевод премиум-DLC через Workshop **легитимно**: айтему ставится флаг
«требует DLC X» (чекбокс на каждое из DLC на странице айтема) → Steam отдаёт его
ТОЛЬКО владельцам этого DLC, контент остаётся за пейволом. Это БОЛЕЕ корректно, чем
форумы/Vault/Yandex (без гейта). «Премиум» = обычное платное DLC; база и DLC
одинаково платные, разницы для перевода нет. Копирайт-claim в описании не ставим —
хватает тега `[AI]` (см. провенанс в памяти проекта).
